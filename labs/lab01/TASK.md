# ЛР1. Контекст проверки риска

Вариант: **Fraud**.

## Что дано

Функция `calculate_risk(dict)` уже рассчитывает баллы. Все тесты проходят.

## Задание

Создайте `FraudCheckContext` и `FraudService`. Данные одной проверки должны храниться в объекте контекста, расчёт — выполняться сервисом. Готовый `FraudResult` используйте для ответа.

Две существующие проверки пока можно оставить обычными условиями. Расчёт каждого запроса должен начинаться заново.

## Примеры и границы

- `100 EUR` в `RESTAURANT` дают `0` баллов и `ALLOW`.
- `1000.01 EUR` в `RESTAURANT` дают `40` баллов; `100 EUR` в `GAMBLING` — также `40`.
- Оба признака дают `80` баллов и `DECLINE`.
- Безопасный запрос после рискованного снова даёт `0`.

Все проверки открыты: `tests/test_contract.py` и `tests/test_review_contract.py`.
Описание объектов — в [REFERENCE.md](REFERENCE.md), исходные результаты тестов — в [STARTER-STATE.md](STARTER-STATE.md).

## Проверка и защита

Из корня проекта выполните `python check.py lab01`.

Покажите данные одной проверки. Объясните, почему баллы не должны переноситься между запросами.

Работа сдана, когда все обязательные тесты проходят, изменения из задания выполнены,
а оба участника внесли содержательные коммиты и могут объяснить решение.
