# ЛР3. Правила начисления баллов

Вариант: **Fraud**.

## Что дано

Предметные объекты, внешний API и вспомогательные типы уже подготовлены. В `app/domain/risk_rules.py` даны заготовки общего интерфейса и двух исполнителей. Их поведение и основной метод `FraudService.check()` требуется завершить самостоятельно. Сигнатуры сохранены; новые слои и выбор архитектуры не нужны.

## Задание

### Шаг 1. Реализуйте общий интерфейс и два поведения

Реализуйте `FraudRule`, `LargeAmountRule` и `HighRiskMerchantRule`.

`LargeAmountRule` даёт `40` баллов при `amount > 1000 EUR`, код — `LARGE_AMOUNT`. `HighRiskMerchantRule` даёт `40` баллов для `GAMBLING`, код — `HIGH_RISK_MERCHANT`. В остальных случаях вклад равен нулю.

Сервис вызывает `evaluate()` у всех правил, собирает коды положительных вкладов по порядку и ограничивает только итоговый балл значением `100`. Неверный вклад отдельного правила не исправляется автоматически.

### Шаг 2. Соберите путь вызова в `FraudService.check()`

Проверьте тип контекста (`INVALID_CONTEXT`), получите вклад каждого правила через `evaluate()` и готовую `risk_points()`. Ограничьте итог ста баллами; коды ненулевых вкладов сохраняйте без повторов в порядке правил. Даже после достижения 100 остальные правила должны быть вызваны. Не выбирайте алгоритм по конкретному классу исполнителя.

### Шаг 3. Проверьте повторное использование

Безопасный запрос → 0/ALLOW; большая сумма у рискованного магазина → 80/DECLINE; безопасный запрос снова → 0/ALLOW.

## Примеры и границы

- Сумма `1000` не срабатывает, `1000.01` даёт `40` баллов.
- `GAMBLING` даёт `40`; вместе два признака дают `80`.
- Три контрольных вклада `40 + 40 + 40` дают итог `100` и все три кода.
- Вклад `101` от одного правила — ошибка.

Последовательности и конфигурации дополнительно проверяются в `tests/test_progression.py`. Прочитайте ожидаемый результат каждого сценария до реализации.

Все проверки открыты: `tests/test_contract.py` и `tests/test_review_contract.py`.
Описание объектов — в [REFERENCE.md](REFERENCE.md), исходные результаты тестов — в [STARTER-STATE.md](STARTER-STATE.md).
